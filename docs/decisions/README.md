# Architecture Decision Records

Use lightweight Architecture Decision Records (ADRs) for material choices that affect architecture, security, data handling, dependencies, operations, or difficult-to-reverse behavior. Create one Markdown file per decision, with a date and concise slug in its filename. Record decisions when they are made; do not present proposals as adopted decisions.

Each record should contain:

## Decision

State the chosen direction, its status, and relevant context.

## Alternatives

List credible alternatives considered, including retaining the current design when applicable.

## Why Chosen

Explain the evidence, constraints, and product or engineering goals behind the choice.

## Tradeoffs

Record benefits, costs, risks, limitations, and consequences without hiding uncertainty.

## When to Revisit

Define measurable triggers, changed assumptions, or evaluation results that should cause the decision to be reviewed.
